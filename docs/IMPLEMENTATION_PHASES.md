## Implementation Cadence

Preferred implementation cycle:

```txt
one subsystem at a time
one orchestrator at a time
one consolidation phase at a time
```

This reduces:

- timeout probability
- connector stress
- rendering load
- recursive architectural drift

## Stability Rules

Every batch should:

1. verify previous routes still mount
2. avoid simultaneous rewrites
3. keep commits focused
4. fail soft when optional modules break
5. preserve Render stability

## Session Rotation Rule

At this scale, implementation threads should periodically rotate.

New threads should summarize:

- current repo state
- current architecture
- current orchestration phase
- current adapters connected
- next safe batch

This reduces:

- context overload
- memory drift
- rendering pressure
- repeated explanations
