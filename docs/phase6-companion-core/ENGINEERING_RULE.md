# BibleBuddy Enterprise Engineering Rule

No new feature, route, owner, helper, runtime, AI tool, API integration, memory engine, doctrine pack, or UI component enters BibleBuddy unless it answers YES to all five:

1. Does it simplify the architecture?
2. Does it strengthen the Companion Core?
3. Does it preserve Scripture as final authority while keeping one consistent companion voice?
4. Does it follow enterprise/industry-standard architecture for scale, maintainability, testing, observability, security, and production readiness?
5. Does it review and learn from prior BibleBuddy files, audits, coding mistakes, regressions, route conflicts, and fixes so we do not repeat the same problems?

If any answer is NO, redesign before implementation.
