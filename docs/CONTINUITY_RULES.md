# BibleBuddy Continuity Rules

## Purpose

The Continuity Rule Engine exists to prevent fragmented user experiences.

BibleBuddy should feel:

- coherent
- gentle
- ordered
- explainable
- Scripture-aware
- pastorally sensitive

not:

- chaotic
- fragmented
- overwhelming
- repetitive
- disconnected

## Core Principle

Prefer:

```txt
one coherent next step
```

instead of:

```txt
many disconnected suggestions
```

## Continuity Priorities

### 1. Spiritual Continuity

Maintain:

- discipleship flow
- prayer continuity
- worship continuity
- covenant understanding
- doctrine consistency

### 2. Emotional Continuity

Avoid:

- harsh transitions
- overwhelming recommendation bursts
- contradictory guidance
- insensitive tone shifts

### 3. Runtime Continuity

Preserve:

- compressed memory summaries
- continuity stage
- active discipleship themes
- recurring prayer themes
- stewardship goals

## Compression Rule

Runtime memory should be compressed into:

```txt
safe continuity summaries
```

instead of storing excessive raw runtime detail.

## Doctrine Rule

All continuity output must pass through:

```txt
DoctrineIntegrityPipeline
```

before user-facing compilation.

## User Journey Rule

The engine should determine:

- what stage the user is in
- what the user already learned
- what should happen next
- what should NOT happen yet

## Example Flow

```txt
User Prayer Signal
        ↓
Prayer Adapter
        ↓
CanonicalOrchestrator
        ↓
ContinuityRuleEngine
        ↓
DoctrineIntegrityPipeline
        ↓
UnifiedDiscipleshipCompiler
```

## Runtime Safety Rules

Avoid:

- manipulative language
- fear-driven responses
- coercive spiritual pressure
- false certainty
- fabricated prophecy
- fabricated Scripture

## Gentle Guidance Rule

Outputs should:

- encourage
- guide
- support
- teach
- invite

without aggressive pressure.
