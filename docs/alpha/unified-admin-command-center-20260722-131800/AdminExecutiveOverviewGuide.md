# Admin Guide — Executive Overview

Where: Admin page → **★ Command Center** tab (now the default tab that
loads first) → "Executive Overview" panel.

## What it answers, at a glance

The Executive Overview always shows five plain-language answers at the
top:

1. **Is BibleBuddy healthy?** — YES / NO / DEGRADED, based on live
   runtime health plus any Critical/High alerts.
2. **Are users encountering problems?** — count of failed requests
   recorded since the server process started.
3. **Are responses accurate & Scripture-aligned?** — count of flagged
   doctrine issues and the fallback-response rate, when measurable.
4. **What decisions need attention?** — total open Decision Queue items,
   broken out by Critical/High count.
5. **What should I do today?** — one recommended next action (resolve
   Critical alerts first, then High-severity queue items, otherwise
   routine review).

Below that, six summary cards give one line each for: System Health,
User Activity, Response Quality, Scripture & Knowledge, Lesson
Alignment, and Admin Decisions. Each card shows a colored status badge
(OK / DEGRADED / ERROR / UNAVAILABLE), which existing system it is
sourced from, and whether the data is LIVE, CACHED, or a SNAPSHOT — plus
a "drill down →" link that jumps straight to the relevant existing tab
for full detail.

## Reading the status badges

| Badge | Meaning |
|---|---|
| OK | The underlying system responded normally. |
| DEGRADED | The underlying system responded, but with a partial or stale result. |
| ERROR | The underlying system could not be reached this request; see the errors list on that card. |
| UNAVAILABLE | The underlying system is not configured/enabled in this environment. |

If any card shows ERROR or UNAVAILABLE, the rest of the Overview still
loads normally — one subsystem being down never blocks the whole page.

## Freshness indicators

- **LIVE** — read directly from the running server's current in-memory
  state (e.g., runtime health, active alerts).
- **CACHED** — read from an existing pre-computed store that refreshes
  on its own schedule (e.g., Knowledge Coverage snapshots).
- **SNAPSHOT** — a point-in-time report generated by an existing offline
  process (e.g., the latest Founder Readiness Validator run).

## Where the numbers come from

Nothing on this page is invented. Every number traces back to one
specific existing system (shown as `source: ...` under each card):
`runtimeHealthMonitor`, `knowledgeAnalyticsSnapshotStore`,
`lessonScriptureAlignmentAnalyzer`, `founderOperationalIntelligenceEngine`,
`adminAlertCenter`, and `adminDecisionQueue`. If a number cannot be
computed honestly (e.g., no prior comparison window exists yet), the
Overview says so explicitly rather than guessing.

## What to do from here

- If everything shows OK and 0 Critical/High alerts: no action needed —
  check the Daily Briefing panel for routine items.
- If a card shows a problem: click "drill down →" on that card to open
  the relevant existing tab (Scripture Authority Review, Engineering
  Intelligence, Founder Readiness, or Founder Intelligence) for full
  detail and to take action there.
- For a narrated summary instead of reading the cards yourself, ask the
  AI Chief of Staff "What needs my attention today?" (see
  `AdminAIChiefOfStaffGuide.md`).
