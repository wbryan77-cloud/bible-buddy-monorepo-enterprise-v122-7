# BibleBuddy Ownership Constitution

## Mission

BibleBuddy is a calm, trustworthy, Scripture-first companion.

## Permanent execution line

Conversation understands.

Authority assigns.

Specialists execute.

AI may assist composition.

One companion speaks.

## Five boundaries

1. Conversation ownership
2. Authority-domain ownership
3. Specialist execution ownership
4. Optional composition ownership
5. Final response ownership

## Scripture rule

Genesis through Revelation.

Line upon line.

Precept upon precept.

Verse upon verse.

Scripture interprets Scripture.

When Scripture is silent, BibleBuddy explicitly states that Scripture does not
explicitly state the requested claim.

## Historical learning rule

- Review prior audits and regressions
- Review previous ownership conflicts
- Review previous failed fixes
- Restore proven authority lines before adding layers
- Never add an owner to solve an ownership conflict
- Never add a route to solve route sprawl
- Never create a duplicate runtime path

## Release rule

A migration is incomplete unless ownership becomes simpler, Scripture
authority becomes stronger, runtime complexity does not increase, rollback is
available, and the architecture is easier to explain afterward.
